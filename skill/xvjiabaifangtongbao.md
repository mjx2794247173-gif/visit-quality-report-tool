# 虚假拜访通报工具｜工作规范

## 目标与边界

该工具读取 CRM 已质检 Excel，在浏览器本地按日期、省区、实际拜访方式汇总并生成重点案例通报。

`质检问题类型` 是唯一事实来源。不得查看照片、比较反馈文本或自行判断站长是否虚假拜访；工具只汇总、排序和表达 CRM 已识别结果。默认不连接 CRM，也不上传或保存用户文件。

## 导出字段与解析

按表头名称识别字段，不按列号。核心字段：

| 用途 | CRM 列名 |
| --- | --- |
| 拜访唯一标识 | `拜访编码` |
| 客户 | `客户编码`、`客户名称` |
| 人员 | `拜访人ERP` |
| 省区 | `拜访人主导省区` |
| 时间 | `实际拜访时间` |
| 拜访方式 | `实际拜访方式` |
| 问题 | `质检问题类型` |

CRM xlsx 可能把工作表 dimension 错写为 `A1`。解析时直接遍历 `xl/worksheets/sheet1.xml` 中的行与单元格，不能只依赖 dimension。

## 数据口径

- 日期范围包含开始和结束日期；实际拜访方式支持全部、微信、电话、上门。
- 从逗号分隔的 `质检问题类型` 中移除 `反馈内容无意义`；若一条记录只剩该问题，则不参与评分、候选或通报。
- 候选按 `拜访人主导省区 + 拜访人ERP` 聚合；所选范围内按总分取前三。
- 虚假拜访数按去重后的 `拜访编码` 计算；客户数按去重后的 `客户编码` 计算；持续天数按去重后的实际拜访日期计算。

## 评分（总分 100）

评分只用于排序选案例，不能出现在最终通报。所有分数使用所选范围内的实际数量，不做周期折算。

| 维度 | 阶梯 | 分值 |
| --- | --- | --- |
| 虚假拜访数 | 1–2 / 3–5 / 6–10 / 11–20 / ≥21 | 8 / 16 / 26 / 36 / 45 |
| 问题类型数 | 1 / 2 / 3 / ≥4 | 5 / 12 / 19 / 25 |
| 异常持续天数 | 1 / 2 / 3 / 4–5 / ≥6 | 3 / 6 / 9 / 12 / 15 |
| 涉及客户数 | 1 / 2–3 / 4–6 / 7–10 / ≥11 | 2 / 5 / 8 / 12 / 15 |

例如，5 次虚假拜访是 16 分，6–10 次才是 26 分。总分相同时，以最近实际拜访时间排序。候选表可展示总分和拆分，并提供 `!` 悬浮说明完整规则。

## 通报文案

候选标题使用 `省区—ERP`，不要求站点名称。最终通报不写总分、得分拆分、原始记录总数或问题类型数量。

每个案例固定为：

```text
案例一：{省区}—{ERP}
（{开始月日}至{结束月日}共疑似虚假拜访{去重拜访编码数}次，其中{问题类型A}{次数}次、{问题类型B}{次数}次）
涉及拜访编码：{拜访编码列表}
```

日期格式为 `10-01至10-07`，不要显示年份。表达 CRM 识别结果时使用“疑似虚假拜访”或“CRM 已质检”，不要说工具确认了虚假。

## 页面体验

- 顶部为深色标题区；主体使用浅色背景和白色工作卡片。
- 上传区仅保留“选择文件”和“使用示例数据”；示例数据必须虚构。
- 文件状态说明本地解析、不上传、不长期保存。
- 筛选与候选结果保持白底黑字。统计卡只保留：`条虚假拜访`、`个涉及站长`、`当前省区`；不显示最高分卡。
- 通报预览为独立黑底白字区域；底部“复制通报全文”为整行白底黑字按钮。
- 顶部支持文案固定为：`网页问题、数据问题、bug 请联系 mengjiaxi.1`。
