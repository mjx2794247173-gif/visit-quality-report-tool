# 省区拜访质量智能分析助手：项目设计规范

这份文档是项目公开版规范，帮助开发者和面试官理解系统边界。它不是运行时配置，也不包含任何 API Key 或本机路径。

## 项目定位

系统面向省区用户，处理 CRM 导出的拜访质检数据，提供确定性数据分析、业务规则检索和自然语言解释。真实 Excel 默认只在当前浏览器会话和本地后端处理。

## 核心链路

```text
用户问题
  → LangGraph Supervisor 判断分支
  → DeepSeek 理解问题并提取省区/ERP/指标/排序/日期条件
  → Function Calling 选择白名单工具
  → FastAPI 执行确定性分析工具或 RAG 检索
  → 校验工具结果和统计范围
  → 将结构化结果回传 DeepSeek
  → 生成自然中文回答
```

数据问题也必须先经过模型意图理解；模型不能自行计算关键数字。

## 确定性工具

- `problem_type_ranking`：按拜访条数统计问题类型排名。
- `station_summary`：查询指定省区重点站长摘要。
- `station_lookup`：按站长 ERP 查询当前上传文件中的站长情况。
- `station_multi_problem_types`：查询涉及多类问题的站长。
- `consecutive_problem_days`：按去重自然日计算连续问题天数。
- `repeated_customers`：查询同一客户对应多个拜访编码的情况。
- `explain_score`：解释已有重点排序，不创造评分规则。
- `data_quality_check`：检查字段和可分析性。
- `generate_bulletin_summary`：生成指定省区的确定性摘要。

所有工具只读、白名单执行，结果必须经过校验后才能交给模型。

## 统计边界

- 事实来源只包括 CRM 已有的“质检问题类型”。
- 不看照片，不比较反馈内容，不自行判断虚假拜访。
- “问题最多”默认按对应拜访条数统计。
- `反馈内容无意义`不参与问题计数、站长候选、评分、排名、摘要或模型上下文。
- 用户指定省区时，记录数、问题排名和站长列表必须使用同一省区范围。
- 输入“上海/上海省/上海省区”等写法时，后端需要做省区名称归一化。

## RAG 边界

向量库只保存评分规则、字段字典、CRM 导出要求、统计口径、通报模板、FAQ、常见报错和安全边界。真实 CRM 行级数据不能写入长期向量库、日志或用户画像。

## 上下文与回答

前端只向后端发送必要的聚合摘要和站长索引，不发送完整 Excel 行级记录。数据量较大时必须压缩上下文，不能把完整 JSON 展示给用户或让请求因大小限制失败。

最终回答只展示自然语言结论、关键数字、统计口径和依据，不展示原始 JSON、工具参数、内部提示或思维过程，也不主动追加用户没有询问的省区摘要。

## 评测重点

固定测试应覆盖：省区问题排名、ERP 查询、站长问题排名、连续日期、多类问题、重复客户、评分解释、指定省区摘要、字段缺失、超大数据摘要、模糊问题和越权问题。
