# 工具调用规范

## 标准链路

```text
用户问题
  → LangGraph Supervisor 判断分支
  → DeepSeek 理解条件并选择白名单工具
  → FastAPI 执行确定性工具或 RAG 检索
  → 校验结构化结果
  → 回传 DeepSeek
  → 生成自然语言回答
```

即使是数据问题，也必须先由模型识别省区、ERP、指标、排序和日期范围，再调用工具。模型不能自行计算关键数字。

## 确定性工具

- `problem_type_ranking`：问题类型排名。
- `station_summary`：省区重点站长摘要。
- `station_lookup`：按站长 ERP 查询当前文件中的站长情况。
- `station_multi_problem_types`：多类问题站长。
- `consecutive_problem_days`：连续多天问题。
- `repeated_customers`：重复客户。
- `explain_score`：重点站长评分解释。
- `data_quality_check`：数据质量检查。
- `generate_bulletin_summary`：指定省区通报摘要。

所有工具只读、白名单执行，工具结果必须校验后才能交给模型。

## RAG

RAG 只保存评分规则、字段字典、CRM 导出说明、统计口径、通报模板、FAQ、常见报错和安全边界。真实 CRM 行级数据不能写入长期向量库。

## 会话与回答

当前上传文件、筛选省区、ERP 和最近问题可以保留在短期会话中。前端只发送必要的聚合摘要和站长索引，不发送完整 Excel 行级记录；大数据量必须做上下文压缩。

最终回答只展示自然语言结论、关键数字、统计口径和依据，不展示原始 JSON、工具参数、内部提示或思维过程，也不主动追加用户没有询问的省区摘要。

## 多轮 Function Calling

第一轮必须返回工具调用；FastAPI 执行每个白名单调用并逐个回传 `tool_call_id`。如果 DeepSeek 返回 `reasoning_content`，第二轮必须原样保留 assistant 消息中的该字段。没有经过工具校验的数字不得进入最终回答。

## 飞书发布工具

飞书推送属于有外部副作用的发布动作，不进入 DeepSeek 的自主分析工具列表。页面只能在回答生成后展示“推送飞书”，并要求用户二次确认。

- 使用飞书官方 `@larksuiteoapi/lark-mcp`。
- MCP 只启用 `im.v1.message.create`，消息格式固定为纯文本。
- App ID、App Secret 和接收目标只存在后端 `.env`。
- 接收目标由后端固定，浏览器和模型均不能指定任意群聊。
- 只推送已校验的自然语言汇总，不推送 CRM 行级记录。
- 审计日志只记录工具名、成功状态和耗时，不记录消息正文、密钥或群 ID。
